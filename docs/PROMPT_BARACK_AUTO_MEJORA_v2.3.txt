EVIDENCE GATE (Blake Crosley pattern, 6 criteria — antes de cualquier "done"):
Para cada feature/bug que vas a marcar como `done`:
1. ARCHIVO: existe el archivo modificado/creado (paths absolutos verificables).
2. TEST OUTPUT: hay output de test capturado en `docs/auto-mejora/evidence/<task-id>/test-output.txt`.
3. CODEBASE PATTERN MATCH: el cambio sigue patrones existentes en el codebase (no introduce un nuevo patron sin ADR).
4. NO STUBS: no hay `TODO`, `FIXME`, `throw new Error('not implemented')` introducidos.
5. NO COMMENT-ONLY: el cambio es de codigo, no solo comentarios (salvo que el task sea explicitamente docs).
6. DIVERGENCE <10%: el diff entre lo planeado en feature_list y lo implementado es <10% (lineas o files distintos).

Loguear evidencia en `docs/auto-mejora/evidence/<task-id>/`. Si <6/6 criterios → tarea NO esta `done`.

<heartbeat_protocol>
Path: `BarackMercosul/docs/auto-mejora/heartbeat.log`

FRECUENCIA: al iniciar sesion + al cerrar cada fase + cada 15 min durante fase + ante cualquier bloqueo.

FORMATO (1 linea por entry, separado por `|`, todos los campos obligatorios, timestamp SIEMPRE UTC con `Z` suffix):
```
<ISO-8601-UTC-with-Z> | F<n> | <STATUS> | tokens=<estimate> | last=<archivo:linea> | next=<accion> | tests=<P/F/S> | gates=<A:OK,B:OK,C:FAIL,...> | notes=<one-liner>
```

TIMEZONE POLICY (CRITICA):
- TODOS los timestamps en heartbeat, state.json, learnings_*.md, dossier: ISO-8601 UTC con `Z` suffix.
- Comandos shell: `date -u +%Y-%m-%dT%H:%M:%SZ` (NO `date` local).
- Branch names: `auto-mejora/<UTC-date>_<UTC-time>Z`.
- "Mismo dia" en idempotency = mismo dia UTC (00:00-23:59 UTC), NO local Argentina.
- Si Claude detecta entries con timestamps no-UTC (sin Z): flag CORRUPTED en heartbeat, no procesar.

STATUS valores: STARTING / IN_PROGRESS / GATE_PASSED / GATE_FAILED / EVIDENCE_GATE_PASSED / EVIDENCE_GATE_FAILED / BLOCKED / FASE_DONE / SESSION_DONE / DRIFT_DETECTED / STUCK_LOOP_DETECTED / INTERRUPTED.

Ejemplo:
```
2026-05-08T22:15:30Z | F2 | IN_PROGRESS | tokens=48000 | last=modules/amfe/AmfeApp.tsx:541 | next=fix operationFunction sync AMFE-HRC-PAT | tests=187/0/2 | gates=A:OK,B:OK,C:OK,D:SKIP,E:SKIP,F:OK | notes=AMFE 150 OK, HRC siguiente
```

CAMPOS:
- timestamp UTC con `Z` suffix obligatorio.
- F<n>: F0, F0.5, F1, F2, F3, F4, F5, F6a, F6b, F7.
- tokens: estimate del agente (no exact; usar contador interno).
- last: archivo:linea aproximada del ultimo edit.
- next: 1 frase de la proxima accion concreta.
- tests: P/F/S (passed/failed/skipped) del ultimo `npm test`.
- gates: estado de cada gate A-F en el ultimo gate-run (OK/FAIL/SKIP).
- notes: contexto adicional <100 chars.

RECOVERY (al arrancar nueva sesion):
1. `tail -50 heartbeat.log` — ver donde quedaste.
2. `cat feature_list.json | jq '.tasks[] | select(.status=="in_progress" or .status=="pending")'` — pendientes.
3. `git status && git log --oneline -10` — ultimos cambios.
4. Si ultima entry es FASE_DONE → retomar fase siguiente.
5. Si IN_PROGRESS → continuar misma fase.
6. Si BLOCKED → leer STOP_REQUESTS.md.
7. Si DRIFT_DETECTED → analizar incidente, no continuar sin entender.
8. Si INTERRUPTED → revertir cambios sin commit, continuar desde ultimo commit verde.
</heartbeat_protocol>

<recovery_patterns>
Catalogo de fallas + respuestas codificadas. P1-P12 del v1 + P13-P42 nuevos.

P1 — `tsc --noEmit` falla → no comentar, no @ts-ignore. Fix tipo correcto. Si requiere refactor mayor: revertir + STOP_REQUESTS.

P2 — Test rojo despues de cambio → revertir. Test de regresion PRIMERO. Reaplicar fix con test verde como guia.

P3 — Build rompe en CI pero local pasaba → diff lockfile + Node version. NO parchear. Alinear versiones.

P4 — Supabase error de schema → `information_schema.columns`. NUNCA asumir.

P5 — Lint warning masivo → NO `eslint-disable`. Fix real archivo por archivo.

P6 — Detecto que afirme algo sin verificar → STOP. Revertir si corresponde. `incidentes-alucinacion.md` con timestamp + claim falso + evidencia que faltaba. Activar verify-before-claim.

P7 — Subagent devuelve dossier con paths/lineas que no existen → NO actuar. Re-despachar con "verificar paths leyendo el archivo". Si reincide, hacerlo manual.

P8 — 3 fases consecutivas con gates fallidos → MODO EMERGENCIA. Cerrar ultimo commit verde. Reporte parcial. SESSION_DONE.

P9 — Tiempo se acaba a mitad de fase → priorizar F7 (dossier). NO dejar WIP sucio.

P10 — Repo en estado irrecuperable → `git stash --include-untracked` + `git reset --hard origin/<branch>`. Documentar.

P11 — Bloqueo externo (Supabase down >30 min) → pausar fase dependiente. Avanzar a F4/F5/F6 (no-Supabase). Si todas dependen, esperar 10 min. Si persiste 30 min: BLOCKED.

P12 — Encuentro contenido APQP que parece "incorrecto" pero no estoy seguro → NO modificar. `dudas-apqp-para-fak.md` con contexto + opciones.

P13 — RLS deniega lectura legitima → verificar `information_schema.table_privileges`. Si RLS cambio: comunicar a Fak. Skip esa tabla, avanzar.

P14 — Supabase latencia >2h con recuperation parcial → cambiar timeout a 30s. Pausar fase de datos. Continuar F4/F5.

P15 — Schema cambia bajo nuestros pies → query `information_schema` para schema actual. Adaptar queries o reportar.

P16 — JSONB corrupto (double-serialization) → NO arreglar. Log + reportar. Backup historico.

P17 — Rate limit 429 → backoff exponencial (2s, 4s, 8s, max 3 retries). Serializar operaciones grandes.

P18 — Timeout en queries grandes → paginacion `LIMIT 50 OFFSET 0`. Batches mas pequenos.

P19 — Merge conflicts en branch tras pull simultaneo (multi-PC) → `git rebase --abort` + stash. Reportar a Fak.

P20 — Commit falla por hooks lentos (>2min) → matar con Ctrl+C. Commits mas chicos. Investigar pre-commit.

P21 — Branch protection bloquea push → crear PR para satisfacer requirements. Esperar checks.

P22 — `.git` corrupto → `git fsck --full` + `git gc --aggressive`. Si no repara: re-clone.

P23 — Permissions denied Windows ACL → `tasklist | find "node"` + matar zombies. PowerShell admin si persiste.

P24 — Disk full → liberar espacio. Comprimir backups antiguos. NO borrar (IL-5). Avanzar a fases que no escriben.

P25 — UTF-8 con BOM en archivos generados → leer como buffer, quitar primeros 3 bytes si es BOM.

P26 — Out of memory → `NODE_OPTIONS="--max-old-space-size=4096"`. Serializar operaciones. Restart REPL.

P27 — Otra instancia paralela de Claude Code → detectar via `git status` no-pusheado. `git fetch` + diff. Coordinar.

P28 — Hook script cuelga → matar `killall node`. `HUSKY=0 git commit`. Investigar.

P29 — Dev server zombie → `netstat -ano | findstr :3000` + `taskkill /PID`. Reiniciar.

P30 — Node version mismatch → `node --version` vs `.nvmrc`. `nvm use`.

P31 — MCP server desconectado mid-sesion → reconectar. Fallback (SQL directo en lugar de MCP Supabase).

P32 — WebFetch bloqueado por firewall → leer desde Supabase si esta ingested. Preguntar a Fak.
